## Що таке часові ряди?

**Часовий ряд** — впорядкована послідовність числових значень, кожне з яких асоційоване з певним моментом часу.

**Математично:** {(t₁, v₁), (t₂, v₂), ..., (tₙ, vₙ)}

```mermaid
graph LR
    A[📊 Джерело] -->|t₁, v₁| B[Точка 1]
    A -->|t₂, v₂| C[Точка 2]
    A -->|tₙ, vₙ| E[Точка n]

    B --> F[⏱️ Часовий ряд]
    C --> F
    E --> F
```

**Приклади:** температура сенсорів кожні 10 секунд, ціни акцій щохвилини, метрики серверів у реальному часі

## Властивості та типи часових рядів

**Властивості:**
- 🔄 Монотонність часу (tᵢ < tᵢ₊₁)
- 📍 Обов'язкова часова прив'язка
- 🔒 Незмінність історії
- ⚡ Висока швидкість надходження

**Типи:** регулярні (фіксовані інтервали) vs нерегулярні (реагування на події)

## Виклики роботи з часовими рядами

### 💾 **Високий об'єм даних**

**1 датчик, 1 с інтервал:** 86,400 записів/день → 31.5M записів/рік

**При масштабуванні на тисячі датчиків — астрономічні обсяги**

**Інші виклики:** швидкий запис (B-tree неефективні), необхідність компресії, гарячі vs холодні дані

## InfluxDB

### 📊 **Спеціалізована БД для часових рядів**

```
# Структура точки даних
measurement,tag_key=tag_value field_key=field_value timestamp
temperature,sensor=sensor_01,location=room_1 value=22.5 1642248000000000000
```

```sql
-- Flux запит
from(bucket: "sensors")
  |> range(start: -1h)
  |> filter(fn: (r) => r._measurement == "temperature")
  |> aggregateWindow(every: 5m, fn: mean)
```

> **Актуалізація:** InfluxDB 3.0 (рушій IOx на Rust + Apache Arrow/Parquet) додав нативний SQL і стовпчикове зберігання — Flux лишається для сумісності зі старими проєктами.

## TimescaleDB

**PostgreSQL + Time-Series оптимізації**

```sql
CREATE TABLE sensor_data (
    time TIMESTAMPTZ NOT NULL,
    sensor_id INTEGER NOT NULL,
    temperature DOUBLE PRECISION
);
SELECT create_hypertable('sensor_data', 'time');

-- Компресія + retention
ALTER TABLE sensor_data SET (
    timescaledb.compress,
    timescaledb.compress_segmentby = 'sensor_id'
);
SELECT add_compression_policy('sensor_data', INTERVAL '7 days');
SELECT add_retention_policy('sensor_data', INTERVAL '90 days');
```

**🎯 Коефіцієнт компресії: 90-95%**

## Методи компресії часових даних

**Delta Encoding** — зберігання різниць замість абсолютних значень
**Dictionary Encoding** — словник унікальних значень + компактні посилання
**Gorilla Compression** (Facebook) — XOR операції для плаваючої коми, 10–20x стиснення

## Збір та обробка IoT-даних

```python
class IoTDataCollector:
    def on_message(self, client, userdata, msg):
        data = json.loads(msg.payload)
        point = Point("sensor_reading") \
            .tag("sensor_id", data['sensor_id']) \
            .field("temperature", data['temperature']) \
            .time(data['timestamp'])
        self.write_api.write(bucket="sensors", record=point)
```

**Пакетна обробка (batching):** запис пакетами замість поодиноких вставок — приріст продуктивності на порядки

**Stream processing:** Kafka/Flink (див. лекцію 14) + ковзне вікно для виявлення аномалій (Z-score)

## Edge Computing: концепція

```mermaid
graph TB
    A[IoT Пристрої] --> B[Edge Gateway]
    B --> C{Локальна обробка}
    C -->|Критично| D[Актуатори]
    C -->|Агреговано| E[Хмара]
    B --> G[Локальна БД]
    G -.->|Sync| E
```

**Переваги:** знижена латентність, економія пропускної здатності, приватність, автономність при втраті зв'язку

> **Актуалізація:** на edge-пристроях дедалі частіше запускають TinyML-моделі для inference (ONNX Runtime, вбудовані NPU) — межа між "правилами" й "AI" на краю мережі стирається (див. лекцію 16).

## Розподілена аналітика

**Федероване навчання:** кожен edge-вузол навчає модель локально й надсилає лише градієнти (не самі дані) → приватність

**Ієрархічна агрегація:** Edge → Regional Aggregator → Cloud → Global Analytics

**Offline-first:** обробка незалежно від з'єднання, черга для пізнішої синхронізації, conflict resolution (Last Write Wins)

## **Висновки**

**Часові ряди:** спеціалізовані БД (InfluxDB 3.0, TimescaleDB, QuestDB), компресія 90-95%, багаторівнева агрегація

**IoT-системи:** MQTT, потокова обробка, виявлення аномалій у реальному часі

**Edge Computing:** знижена латентність, автономність, федероване навчання, дедалі частіше — і TinyML inference на пристрої

**Практичні застосування:** промисловий моніторинг, розумні будівлі, точне землеробство
